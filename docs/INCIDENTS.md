# Журнал подтверждённых ошибок manager-client

## Проверки цвета и подготовки окна отстали от интерфейса (21.10.2026)

- **Поведение:** проверка цвета искала старые отдельные контактные поля,
  а проверка задержки окна пыталась измерить промежуточную прозрачность
  уже после окончания анимации.
- **Предотвращение:** использовать нынешнюю форму с единым контактом. Состояние
  подготовки измерять внутри браузера по кадрам во время задержки, не по
  моменту возврата автоматизированного клика.
- **Проверка:** widget-theme.spec.ts проверяет обе ширины с текущей формой;
  panel-motion.spec.ts проверяет несколько скрытых кадров и отсутствие
  видимых частей окна до разрешения подготовки.

## Остатки шапки и внутренняя обводка после закрытия (21.10.2026)

- **Поведение:** после закрытия пользователь видел точку у кнопки и внутреннюю
  обводку. Постоянную точку на текущем стенде повторить не удалось; её положение
  совпадает с индикатором аватара оставшейся под кнопкой панели.
- **Причина обводки:** закрытие всегда возвращало фокус на новую кнопку запуска,
  включая мышь и касание. Браузер мог применить к ней клавиатурный focus-visible.
- **Защита от остаточной отрисовки:** завершённое закрытие обрезает всю панель
  через clip-path и обнуляет её прозрачность. Дочерний стиль аватара не может
  сделать часть закрытой панели видимой. Компоненты не удаляются, поэтому
  черновик и состояние редактора сохраняются.
- **Подготовка редактора:** display: none оказался несовместим с предварительной
  загрузкой эмодзи, которая проверяет геометрию элементов. Скрытая панель сохраняет
  размеры для этой подготовки, но полностью исключена из отрисовки и взаимодействия.
- **Фокус:** возвращать его на кнопку только после клавиатурного закрытия;
  доступный контрастный индикатор для клавиатуры сохраняется.
- **Проверка:** launcher-close.spec.ts покрывает мышь, касание, уменьшение
  анимации, повторное открытие с черновиком, Escape и Enter. До исправления
  проверка закрытия мышью падала на неожиданном фокусе кнопки.

## Кнопка примера не меняет виджет (21.10.2026)

- **Поведение:** после нажатия примера CSS пользователь не видит изменений
  виджета и считает кнопку неработающей.
- **Причина:** обработчик менял только JSON редактора. Для перезапуска виджета
  требовалось отдельное нажатие «Применить конфиг».
- **Предотвращение:** готовые примеры сразу проходят общую валидацию и применяются.
  Пример мессенджеров включает MAX, Telegram и ВКонтакте, отключает отложенное
  открытие переписки и объясняет, как открыть меню каналов. Ручной JSON применяется
  отдельной кнопкой; ошибочный конфиг не уничтожает работающий виджет.
- **Проверка:** браузерный тест нажимает только кнопку примера, проверяет цвет,
  три ссылки, новую надпись «Написать сообщение» и единственный iframe.

## Тест мессенджеров теряет свой конфиг после обновления Vite (21.10.2026)

- **Поведение:** автоматический тест ожидает три мессенджера, но видит только
  исходную серверную ссылку ВК.
- **Причина:** подмена демостраницы ожидала адрес `demo/host.ts` без параметров,
  а после горячего обновления Vite запрашивает его с параметром версии.
- **Предотвращение:** перехватывать точный путь модуля с необязательной строкой
  параметров. Не расширять перехват на остальные файлы приложения.
- **Проверка:** сценарии `messenger-links.spec.ts` проходят на работающем
  сервере разработки после изменения исходников.

## Vue-файлы не распознаются при проверке через Bun (13.10.2026)

- **Поведение:** в `oven/bun:1.3.14-alpine` проверка сообщает TS2307 для
  `Widget.vue` и `SupportWidget.vue`, хотя файлы присутствуют и Vite их собирает.
- **Причина:** без Node.js Bun автоматически подменяет Node-исполнение CLI.
  Используемый `vue-tsc` подключает поддержку Vue через перехват чтения модулей
  TypeScript; этот механизм не работает в проверенном Bun 1.3.14. Один и тот же
  код воспроизводит отказ через Bun и успешно проверяется через Node.js 22.
- **Предотвращение:** выполнять `vue-tsc` через явный Node.js, проверять среду
  запуска и сообщать об отсутствующем инструменте до обращения к TypeScript.
  Не маскировать отказ декларацией `*.vue`, отключением строгих типов или
  заменой проверки успешной сборкой Vite. Node.js требуется сборочному окружению,
  а не серверу готового виджета.
- **Проверка:** отказ при подмене Node на Bun; корректный импорт Vue проходит,
  реальные ошибки внутри компонента и шаблона отклоняются. Фикстуры создаются
  в отдельных временных каталогах и удаляются только после проверки пути.

## Обработка отмены скачивания и сбоя закрытия окна (13.10.2026)

- **Поведение:** отмена скачивания могла возвращать внутреннюю ошибку браузера,
  а после неудачного закрытия следующее открытие повторяло неисправную анимацию
  и ожидало её тайм-аут.
- **Причина:** `download` очищал ресурсы, но не преобразовывал сетевые ошибки
  в `ServiceError`; `closeChat` не проверял отрицательное подтверждение хоста.
- **Предотвращение:** сохранять уже сформированные ошибки сервиса, преобразовывать
  прочие ошибки скачивания в понятный отказ связи и отключать анимацию хоста
  после неуспешного закрытия. Очистка контроллеров и таймеров остаётся обязательной.
- **Проверка:** настоящая отмена запроса по AbortSignal, сетевой отказ, ошибка
  чтения файла и сохранность ServiceError; браузерные сценарии отказа и тайм-аута
  закрытия проверяют, что следующее открытие не обращается к неисправному хосту.
- **Тестовый контур:** порт страницы `MANAGER_TEST_HOST_PORT` не может совпадать
  с фиксированным портом демо API 4311. Проверки сохраняют ограничения диапазона
  и целого значения. Команда запуска демо использует тот же выбранный порт
  страницы при запуске, проверке готовности и выводе адреса. Порт самого демо API
  не меняется.

## Переписка пропадает из виджета после перезагрузки (12.10.2026)

- **Поведение:** посетитель отправляет сообщение и получает ответ, но после
  перезагрузки сайта видит новый пустой диалог. Исходные сообщения остаются
  на сервере, а доступ к своей сессии теряется в браузере.
- **Причина:** гостевой bearer-токен жил только в памяти WidgetApi. В localStorage
  сохранялся visitorToken для квот, который не подтверждает право чтения истории.
  Сервер уже поддерживает возврат snapshot по действующему гостевому токену.
- **Предотвращение:** сохранять только гостевой ключ публичного виджета с разделением
  по сервису, siteId и действительному origin родителя. Историю получать с сервера,
  не связывать доступ по телефону/email или visitorToken. Сбрасывать ключ после
  HTTP 401 либо по истечении локального срока 24 часа, но не из-за сетевой ошибки. Не сохранять токен авторизованной
  поддержки, тексты, контакты, черновики или файлы. Учитывать отказ хранилища
  и не переносить загрузки/операции между старой и новой сессиями.
- **Проверка:** модульные проверки хранения и авторизации; полный браузерный набор,
  включая перезагрузку, переход на другую страницу, истёкшую сессию и production
  loader/iframe на разных origin. Продовая отправка реальным клиентам не используется.
  Если 4310 занят рабочим интерфейсом, задать `MANAGER_TEST_HOST_PORT` со свободным
  портом для страницы теста и `CI=1`, чтобы не переиспользовать чужие процессы.
  Демо API 4311 и preview 4312 должны быть свободны. Тестовый сервис не заменяет
  настоящий manager-server и не взаимодействует с продовыми базами.

## Ограничение хранения публичного виджета 24 часами (13.10.2026)

- **Правило:** серверная переписка в Чате не удаляется из-за срока виджета.
  Только публичный виджет забывает ключ доступа, загруженную историю, контакты,
  черновик, выбранные файлы и состояния незавершённых операций через 24 часа.
- **Причина:** localStorage не имеет автоматического срока жизни, а истечение
  серверного ключа само по себе не очищает уже показанную в браузере переписку.
- **Предотвращение:** хранить только ключ и конечную дату, не продлевать дату при
  восстановлении, проверять срок таймером, при возвращении во вкладку, перед
  обработкой сообщений и отправкой. Поздние ответы и загрузки старой сессии не
  должны восстановить очищенные данные. Авторизованная поддержка не затрагивается.
  Старый формат ключа получает конечный срок один раз при обновлении.
- **Ограничение браузера:** закрытая или замороженная вкладка не выполняет код.
  Просроченный ключ удаляется при следующем запуске/возвращении до использования
  истории; закрытую вкладку невозможно принудительно очистить фоновым таймером.
  Серверное истечение доступа может наступить раньше локальных 24 часов.
- **Проверка:** границы срока, отсутствие продления, отказ хранилища, старый формат,
  независимость поддержки, поздний ответ и ключ другой вкладки; браузерные проверки
  очистки по таймеру, возвращения во вкладку и перезагрузки. Проверяется сохранность
  сообщений демосервера и отсутствие запросов DELETE. Серверный код и миграции
  не меняются. Скачанные самим посетителем файлы не удаляются с его устройства.
