# Размещение виджета: инструкция для команды PKSEP

Внутренний документ для нашей команды размещения и администратора
`manager-server`. Сборку, раздачу файлов, настройки сервиса и разрешение доменов
выполняем мы. Разработчику стороннего сайта передаём готовый код подключения;
он не должен собирать виджет, размещать его файлы или настраивать наш сервер.

Инструкция для интегратора сайта находится в
[SITE_INTEGRATION.md](SITE_INTEGRATION.md).

Посетитель пишет в виджете, обращение появляется в СЭП Чате → «Клиенты»,
а ответ оператора возвращается на сайт. Встраивать весь СЭП Чат или устанавливать
Vue в проект сайта не требуется: загрузчик создаёт отдельный iframe.

Документ описывает публичный виджет сайта. Встроенная поддержка авторизованных
клиентов — другой режим: её нельзя подключать публичным `siteId` без серверной
авторизации.

## 1. Подготовить адреса

Файлы виджета и `manager-server` используют один домен —
`https://manager.pksep.ru`. Адреса подключаемого сайта и `siteId` ниже остаются
примерами: перед выдачей кода замените их данными конкретного сайта.

| Значение             | Пример                     | Назначение                                        |
| -------------------- | -------------------------- | ------------------------------------------------- |
| Адрес сайта          | `https://example.com`      | Страницы, где посетитель открывает виджет         |
| Адрес файлов виджета | `https://manager.pksep.ru` | Статический HTTPS-хостинг сборки `manager-client` |
| `serviceUrl`         | `https://manager.pksep.ru` | Публичный HTTPS-адрес `manager-server`            |
| `siteId`             | `amotiv-site`              | Публичный идентификатор записи сайта на сервере   |

`serviceUrl` указывается без завершающего `/v1/widget`: клиент добавляет этот
префикс сам. Не подставляйте вместо него адрес сервера СЭП Чата.
В коде подключения используйте `serviceUrl: 'https://manager.pksep.ru'`,
не добавляя `/v1/support`, `/v1/widget`, `/v1/channels` или `/internal/staff`.
Поддержка авторизованных клиентов и служебные операции не относятся к публичному
коду подключения. Webhook ВК
`https://manager.pksep.ru/v1/channels/vk/vk-company` настраивается отдельно для
канала ВК, а не вставляется на сайт.

Для внешнего сайта нужны HTTPS-адреса. HTTP допускается только на localhost
для локальной разработки. `siteId` не является секретом и не даёт права
оператора или доступ к чужой переписке.

## 2. Подготовить и разместить сборку

### Если сборка уже подготовлена

Получите весь каталог `dist` от команды проекта. Опубликуйте его содержимое
на статическом хостинге, сохранив структуру и используя файлы одной сборки:

```text
manager.js
manager.mjs
widget.html
assets/
```

Загрузчик и страница iframe доступны по адресам:

```text
https://manager.pksep.ru/manager.js
https://manager.pksep.ru/widget.html
```

Можно разместить сборку в подкаталоге, например `/chat-widget/`:
тогда этот префикс должен присутствовать и в адресе загрузчика, и в `widgetUrl`.
Не переносите `widget.html` отдельно от `assets` и не смешивайте версии файлов.
Пути к ресурсам внутри сборки относительные.

Сервер должен отдавать существующие HTML/JS/CSS-файлы с корректными типами
содержимого. Нельзя заменять отсутствующий JS-файл главной HTML-страницей сайта.
При обновлении сначала публикуйте новые assets, затем HTML/загрузчики;
старые assets сохраняйте на время жизни уже открытых страниц. Не задавайте
длительный неизменяемый кеш для `widget.html`, `manager.js` и `manager.mjs`.

### Если нужно собрать из исходников

Нужен Bun версии, указанной в `package.json` — сейчас `1.3.14`.

```bash
git clone --branch main https://github.com/pksep/manager-client.git
cd manager-client
bun install --frozen-lockfile --ignore-scripts
```

В текущей версии требуется подготовленная сборка `sep_yui` с компонентами
виджета. Одной установки опубликованного пакета недостаточно, если в нём
нет `ChatMessageSurface` и остальных необходимых компонентов.
После установки зависимостей подключите совместимую локальную сборку:

```bash
bun run scripts/use-local-yui.ts /absolute/path/to/built/sep_yui
bun run build
```

`/absolute/path/to/built/sep_yui` — каталог библиотеки с `package.json` и
готовым `dist`, а не URL. Подготовка библиотеки описана в
[README](../README.md#запуск-локального-стенда) и
[SHARED_COMPONENTS.md](SHARED_COMPONENTS.md).
Скрипт подключает библиотеку в установленный пакет потребителя; после новой
установки зависимостей этот шаг нужно повторить. Не заменяйте его ручным
изменением lockfile или неконтролируемым обновлением UI-библиотеки.

Демо `demo/server.ts` и команды `bun run demo`/`bun run dev` предназначены
для разработки, не для продового размещения. В production нужны готовая
статическая сборка и настоящий `manager-server`.

## 3. Разрешить сайт на сервере

Этот шаг выполняет администратор `manager-server`, не разработчик публичной
страницы. Рабочая конфигурация сайтов находится в JSON-файле, путь к которому
задан через `MANAGER_SITES_PATH`.

Файл содержит массив записей. Пример ниже — самостоятельный файл для одного
сайта. Если другие записи уже существуют, добавьте только новый объект
в имеющийся массив, сохранив остальные сайты.

```json
[
  {
    "id": "amotiv-site",
    "name": "Основной сайт",
    "enabled": true,
    "origins": ["https://example.com", "https://www.example.com"],
    "widgetOrigins": ["https://manager.pksep.ru"],
    "config": {
      "company": { "name": "НПО Амотив" },
      "welcomeMessages": ["Здравствуйте!", "Чем можем помочь?"],
      "socialLinks": [],
      "schedule": {
        "timezone": "Europe/Moscow",
        "start": "08:00",
        "end": "18:00",
        "days": [1, 2, 3, 4, 5]
      },
      "contactPolicy": "all",
      "limits": {
        "fileBytes": 10485760,
        "fileCount": 5,
        "messageChars": 10000
      }
    }
  }
]
```

- `id` должен совпадать с `siteId` в коде подключения.
- `origins` — разрешённые адреса **основного сайта**. Укажите отдельно варианты
  с `www` и без него, если оба действительно используются.
- `widgetOrigins` — адреса **размещения iframe**. Именно с этого origin
  браузер обращается к API; CORS сервиса проверяет его.
- В обеих группах нужен точный origin: протокол, домен и порт, если он есть.
  Не добавляйте путь, завершающий `/` или `*`.
- Для публичного виджета не добавляйте поле `support`: такой сайт требует
  отдельную авторизованную сессию поддержки.
- Название компании, приветствия, расписание, лимиты и социальные ссылки
  приходят с сервера. Значения выше — пример, их нужно согласовать с бизнесом.
- `contactPolicy: "all"` требует имя, телефон и email. `"name-and-one"`
  требует имя и хотя бы один контакт; неверно заполненный дополнительный
  контакт тоже блокирует отправку.
- Дни расписания: `0` — воскресенье, `1` — понедельник, …, `6` — суббота.
- Лимит `fileBytes` дополнительно ограничивается серверной настройкой
  `MANAGER_UPLOAD_BYTES`.

После изменения файла перезапустите только соответствующий `manager-server`.
Не удаляйте базы, тома или существующие подключения каналов.

В интегрированном окружении ссылка «Написать ВКонтакте» берётся из настроек ERP.
Она открывает ВК и сама по себе не подключает приём сообщений через Callback API.
Настройка интеграции ВК выполняется отдельно.

## 4. Добавить код на сайт

### Обычный HTML, CMS или конструктор

Добавьте следующий код **один раз**, перед закрывающим тегом `</body>`
или в общий блок скриптов подвала сайта:

```html
<script src="https://manager.pksep.ru/manager.js"></script>

<script>
  if (!window.sepManagerWidget) {
    window.sepManagerWidget = SepManager.mount({
      siteId: 'amotiv-site',
      serviceUrl: 'https://manager.pksep.ru',
      widgetUrl: 'https://manager.pksep.ru/widget.html',
      offset: 24,
    })
  }
</script>
```

`manager.js` — обычный скрипт, предоставляющий глобальный `SepManager`.
Не ставьте `async` на загрузчик в этом примере: инициализация должна выполняться
после его загрузки. `document.body` к этому моменту уже должен существовать.
Защитная проверка не даёт повторной инициализации создать второй виджет.

`offset` — отступ от края окна в пикселях, по умолчанию `24`.
Сам загрузчик ограничивает размеры и положение iframe размерами экрана.
Отдельный контейнер или свои стили кнопки на сайте не нужны.

### Вариант с ES-модулем

Используйте этот вариант **вместо**, а не вместе с предыдущим:

```html
<script type="module">
  import { mount } from 'https://manager.pksep.ru/manager.mjs'

  if (!window.sepManagerWidget) {
    window.sepManagerWidget = mount({
      siteId: 'amotiv-site',
      serviceUrl: 'https://manager.pksep.ru',
      widgetUrl: 'https://manager.pksep.ru/widget.html',
      offset: 24,
    })
  }
</script>
```

При загрузке `.mjs` с другого домена статический сервер должен разрешать
CORS для сайта. Это отдельная настройка от CORS `manager-server`.

### Сайт без перезагрузки страниц

В React/Vue/другом приложении создавайте виджет один раз в корневой части,
когда DOM готов. Не пересоздавайте его при смене маршрута, вкладки или
видимости страницы. При окончательном удалении интеграции вызовите
`destroy()` возвращённого объекта и удалите сохранённую ссылку на него.

Не отключайте виджет на `blur` или при скрытии вкладки: это оборвёт получение
ответов в фоне. Для обычной полной перезагрузки страницы новый экземпляр
создаётся при её следующей загрузке.

## 5. Настроить HTTPS, прокси и защиту браузера

### Сервис сообщений

На публичном адресе `serviceUrl` должны быть доступны `/v1/widget/*`,
включая WebSocket `/v1/widget/events`. Прокси должен передавать WebSocket
Upgrade и не разрывать исправные длительные соединения коротким таймаутом.
Служебные `/internal/*`, базы и очереди нельзя публиковать для подключения сайта.

Сервису нужны доступные зависимости и настроенная связь с СЭП Чатом.
Наличие HTTP-процесса само по себе не означает готовность принимать обращения.
См. [инструкцию развёртывания manager-server](https://github.com/pksep/manager-server/blob/main/docs/DEVOPS_VK_AVITO.md)
и [шаблон входного прокси](https://github.com/pksep/manager-server/blob/main/config/nginx.conf).
Правила проверки origin определяются сервером; не обходите их отключением CORS.

### Политика безопасности содержимого (CSP)

Если на сайте используется CSP, добавьте домен виджета в разрешённые источники
скриптов и iframe, сохранив существующие ограничения. Если запрещены inline
скрипты, вынесите инициализацию в разрешённый JS-файл сайта либо используйте
его штатный nonce. Не ослабляйте всю политику ради подключения.

На хостинге `widget.html` разрешите встраивание только согласованными сайтами
через директиву `frame-ancestors`. `X-Frame-Options: DENY` или `SAMEORIGIN`
заблокирует встраивание с другого домена.
В собственной CSP страницы виджета должны быть разрешены необходимые ресурсы
сборки, запросы к HTTPS API и WSS-соединение с `manager-server`.

### CAPTCHA и файлы

Для внешнего запуска нужна рабочая Яндекс SmartCaptcha и проверка файлов
антивирусом. Режимы без этих проверок допустимы только в изолированной
локальной разработке, не на публичном сайте.

В списке разрешённых доменов SmartCaptcha укажите **домен iframe** —
`manager.pksep.ru`. Настройте её ресурсы в CSP страницы виджета
по [требованиям сервера](https://github.com/pksep/manager-server/blob/main/docs/SECURITY.md).
Проверку с действительными ключами нужно выполнить в браузере до внешнего запуска.

Токены ВК/Авито, ключи Чата/ERP, серверный ключ CAPTCHA и внутренние ключи
интеграции нельзя вставлять в HTML, публичную сборку, URL или логи сайта.
Публичный клиентский ключ SmartCaptcha передаётся самим сервисом при необходимости.

## 6. Проверить приём и ответы

1. Откройте настоящий разрешённый сайт, включая используемые варианты домена.
2. Проверьте в инструментах браузера, что `manager.js`, `widget.html` и assets
   загружаются успешно, без ошибок CSP, CORS и смешанного HTTP/HTTPS.
3. Убедитесь, что создаётся сессия `/v1/widget/session` и устанавливается
   WebSocket-соединение `/v1/widget/events` с подтверждением готовности.
4. Отправьте тестовое сообщение, заполнив необходимые контакты.
5. Оператор с действующим правом «Клиенты» должен увидеть обращение в СЭП Чате.
6. Ответьте из СЭП Чата: сообщение должно появиться на сайте. Начало нового
   набора оператором и новый ответ должны открыть окно виджета без захвата фокуса.
7. После первого действия пользователя на странице проверьте звук нового ответа
   и доставку при переключении на другую вкладку. Набор и прочтение не озвучиваются;
   браузер может ограничивать звук до взаимодействия пользователя.
8. Проверьте отправку разрешённого файла, CAPTCHA, узкий экран и повторное
   подключение после краткого отключения сети.
9. Вне рабочего времени исправный виджет должен оставаться доступным со статусом
   оператора «не в сети». При недоступном сервисе он скрывается до восстановления.

Полностью закрытая страница не получает фоновые уведомления этой интеграции.
Не считайте iframe доказательством доставки push после закрытия браузера.
Полная перезагрузка не гарантирует восстановления анонимной сессии или черновика:
гостевой токен и черновик живут в памяти страницы. Отдельный `visitorToken`
не даёт доступ к истории. Фактический контракт описан в
[RUNTIME_CONTRACT.md](RUNTIME_CONTRACT.md).

## 7. Если виджет не работает

| Симптом                               | Что проверить                                                                                                                                      |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Кнопка не появилась                   | Загрузку файлов, POST сессии, handshake WebSocket, готовность сервиса и зависимости; виджет намеренно скрывается при сбое                          |
| `widget.html` открыт отдельно и пуст  | Это нормально: он ждёт инициализации от родительского сайта                                                                                        |
| `403` при создании сессии             | Точный `siteId`, обе группы разрешённых origin, `enabled`, отсутствие режима `support` для публичного сайта                                        |
| `403` с `code: captcha_required`      | Это запрос проверки, а не запрет сайта; виджет должен показать CAPTCHA и повторить ту же операцию после её прохождения                             |
| Ошибка CORS                           | `widgetOrigins` на API; для ES-модуля — также CORS статического хостинга                                                                           |
| Браузер запрещает iframe              | CSP основного сайта, `frame-ancestors` и `X-Frame-Options` на странице виджета                                                                     |
| Ответы не приходят в фоне             | WebSocket-прокси, разрывы сети и преждевременный `destroy()` при скрытии вкладки                                                                   |
| Звука нет                             | Первое взаимодействие пользователя, настройки звука/автовоспроизведения браузера; отсутствие звука не должно мешать переписке                      |
| Сообщение принято, но «Клиенты» пусты | Проверить отдельно право оператора и ответ API списка обращений; `403` между Чатом и manager-server не исправляется перестановкой скрипта на сайте |
| Файл отклонён                         | Лимит, разрешённый формат, фактическое содержимое, CAPTCHA и доступность антивируса                                                                |

При диагностике фиксируйте маршрут, HTTP-статус и безопасное сообщение ошибки.
Не пересылайте `Authorization`, гостевые токены, контакты посетителей или секреты.
