# manager: переиспользование интерфейса

10.09.2026. Одна ветка `manager` в manager-client, sep_yui и chat_client.
Исходные рабочие копии других задач не редактировались.

## Изменения sep_yui

- `ChatMessageMeta`: добавлен 11.09.2026 как отдельный блок времени и статуса.
  Использует существующие иконки checked/read: одна галочка при отправке,
  две при `isRead`. Входящее сообщение показывает только время. Подключён
  к тексту, контактам и файлам виджета. Существующие поверхности сообщений,
  стандартные настройки и потребители чата этим дополнением не изменены.
- `ChatMessageSurface`: общая оболочка сообщения, входящий/исходящий вариант.
  Режим `unstyled` сохраняет классы и оформление существующего чата. Наружу
  предоставляется DOM-элемент для измерения цитат и отложенной загрузки медиа.
- `ChatFileDetails`: прежние имя/размер и DOM карточки файла; слот сохраняет
  существующее отображение прогресса загрузки в чате.
- `ChatFileIcon`: существующая иконка файла/скачивания/прогресса перенесена
  из чата с её анимацией. Прочие потребители старого composable чата не менялись.
- `ContentEditor.layout='desktop'`: явная полная панель для узкого виджета,
  включая Enter, меню файлов и эмодзи. Без параметра прежняя адаптация сохранена.
- `ContentEditor.suspended`: скрывает диалог вложений свёрнутого виджета,
  сохраняя выбранные файлы; по умолчанию выключен.
- `ContentEditor.preloadEmojiPicker()`: необязательная предварительная подготовка
  панели эмодзи. Виджет вызывает метод в свободное время браузера и сохраняет
  один редактор при смене формы и отправке. Не вызывающие метод потребители
  сохраняют прежний путь открытия панели.
- `ContentEditor.attachmentMode='direct'`: выбор, вставка или перетаскивание
  файлов вызывает штатное `unmount-attach-file` без окна предпросмотра.
  Виджет передаёт файлы в свой существующий процесс отправки/контактов.
  Без параметра сохранён предпросмотр, включая кнопку его подтверждения.
- `ScrollWrapper`: подключён существующий компонент для истории и формы.
  Его реализация не менялась; геометрия и наложение полоски заданы в виджете.
- `Input`: необязательные inputId, ariaLabel, ariaDescribedby для доступной
  формы. Оформление существующих инпутов не менялось.
- `Icon`: добавлены socialVk и socialTelegram. chat/crossSmall переиспользуются.

Размеры и цвета самого виджета заданы только в manager-client. В нём подписи
Input всегда видимы и редактор занимает 120 px. Нижний отступ инструментов —
15 px, полоса прокрутки редактора скрыта. Popover, Avatar и Button сохраняют
свои реализации; внешняя тень отключена только у меню круглой кнопки виджета.
Перетаскивание окна и измерение ширины исходящих плашек реализованы локально.

## Подключение в chat_client

MessageBubbleText, MessageBubbleFiles и MessageBubbleMedia используют общую
оболочку с `unstyled`. FileIcon стал совместимой обёрткой над ChatFileIcon.
Реакции, цитаты, кеш, нативная загрузка и обработчики действий остались в чате.
Не переносились авторизация сотрудников, SDK чата или внутренние media URL
в открытый виджет.

Подключить локальную библиотеку к чистой рабочей копии чата из manager-client:

```powershell
bun run scripts/use-local-yui.ts ../.worktrees/manager-yui-audit ../.worktrees/manager-chat-client
```

Перед этим в чате должен быть выполнен `bun install --frozen-lockfile --ignore-scripts`.
После публикации новой yui нужно обновить версию зависимости в обоих клиентах.

## Проверки

Проверки типов yui и chat_client проходят. Сборки сформировали ES/UMD библиотеки
и приложение чата. Отдельный браузерный сценарий в chat_client запускается так:

```powershell
bun x playwright test --config playwright.manager.config.ts
```

Он проверяет настоящие MessageBubbleText/Files/Media: прежние article/classes,
форматированный текст, имя/размер файла, один вызов действия открытия, загрузку
картинки. Дополнительно проверяет ContentEditor без новых параметров: Enter
отправляет на широком экране, на ширине 418 px сохраняет прежний перенос строки.
Выбор файла в обычном редакторе по-прежнему открывает предпросмотр и ожидает
подтверждения отправки.
Два существующих теста сглаживания прогресса тоже проходят.

Это регрессия общих отображающих компонентов. Полный сценарий комментариев
в работающей ЕРП, системные мобильные клавиатуры и Safari/iOS остаются проверками
перед выпуском общей версии библиотеки.
