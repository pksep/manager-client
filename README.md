# manager-client

Виджет поддерживает Яндекс SmartCaptcha по запросу сервера: клиентский ключ
приходит в ответе проверки, серверный ключ в браузер не передаётся. Для включения
нужны оба ключа в manager-server и разрешённый домен страницы виджета (iframe).
Без ключей интеграция проверяется локальными сценариями с подменённым провайдером.
Отмена или ошибка проверки сохраняет форму для повторной отправки.

Пункт ВКонтакте приходит из конфигурации сервера: источник `VK_BUSINESS_URL`
в ERP. В самостоятельном демосервисе используется одноимённая переменная.
При пустом значении пункт отсутствует.

Открытый виджет обращений для сайта. Посетитель отправляет сообщения и файлы,
а сотрудники отвечают из СЭП Чата.

Задача и рабочая ветка: **manager**. Редакция 0.2 от 10 сентября 2026 года.
Реализован первый этап: виджет и локальный демонстрационный сервис.
Интеграция с настоящим СЭП Чатом и ЕРП выполняется на следующих этапах.

- [Требования к виджету](docs/WIDGET_SPEC.md).
- Общий план находится в репозитории `pksep/manager-server`,
  файл `docs/PLAN.md`.
- Взаимодействие выполняется с `manager-server`; `sep-bot-api` не используется.

Виджет полностью скрыт до подтверждения готовности сервиса принимать обращения.
Недоступность сервиса также скрывает кнопку, меню и окно виджета.
Вне рабочего времени исправный виджет остаётся доступен со статусом оператора
«не в сети».

Основа: Vue 3, TypeScript, Vite, Bun и компоненты `@pksep/yui`.
В репозитории должны находиться только публичные настройки и контракт виджета.
Служебные ключи и учётные данные ЕРП остаются на сервере.

Перед открытым релизом необходимо выбрать лицензию и закрепить условия
распространения переиспользуемых компонентов. Публичность репозитория сама
по себе не задаёт лицензию.

## Запуск локального стенда

Нужны Bun 1.3.14, Node.js 22.12 или новее и сборка **ветки manager** библиотеки sep_yui. Новые общие
компоненты пока не опубликованы в npm. Обычный `bun install` устанавливает
выпущенную 0.1.318; после него необходимо подключить локальную сборку:

```powershell
cd ../.worktrees/manager-yui-audit
bun install --frozen-lockfile --ignore-scripts
bun x vue-tsc --noEmit
bun x vite build
cd ../../manager-client
bun install --frozen-lockfile --ignore-scripts
bun run scripts/use-local-yui.ts
```

Если каталог библиотеки другой, передайте его в `use-local-yui.ts` первым
аргументом. Скрипт копирует сборку в установленный пакет, сохраняя единую Vue
потребителя. Он не меняет package.json, lockfile или исходники библиотеки.
После повторной установки зависимостей повторите этот шаг. После выпуска yui
нужно закрепить новую версию зависимости и убрать необходимость локальной копии.

Проверку типов Vue выполняет Node.js, а Bun остаётся менеджером зависимостей
и запускает штатные команды. В образе `oven/bun:1.3.14-alpine` Node.js отсутствует:
добавьте его в сборочное окружение. Команда `bun run typecheck` явно запускает
проверяющий инструмент через Node.js и не допускает неявной подмены на Bun.
Не добавляйте `--bun`. Сборка Vite сама по себе не заменяет проверку типов.

После подготовки зависимостей запускайте оба процесса одной командой из
`manager-client`:

```powershell
bun run demo
```

После замены локальной сборки sep-yui остановите стенд и один раз запустите
`bun run demo --force`: это штатно пересоберёт кэш зависимостей Vite, чтобы
браузер получил новые экспорты библиотеки. Для отдельного dev-сервера:
`bun run dev --force`.

Дождитесь строки «Демо готово» и оставьте команду работающей. `Ctrl+C`
останавливает оба процесса. После закрытия терминала или перезагрузки компьютера
выполните `bun run demo` снова: ссылка на localhost работает только при
запущенном стенде. Команда заранее проверяет зависимости и свободные порты,
а при остановке одного процесса завершает и второй с сообщением об ошибке.

Для раздельной разработки остаются команды `bun run demo:server` и
`bun run dev` в двух терминалах; первая автоматически перезапускает сервис
при изменениях его исходников.

Открыть **http://127.0.0.1:4310/**. Страница содержит редактор публичного JSON-конфига
`SepManager.mount`. Измените параметры и нажмите «Применить конфиг»: текущий
виджет заменяется одним новым экземпляром. Некорректный JSON не уничтожает
действующее подключение. «Пример с приветствием» вставляет `initialMessage`
и `autoOpenDelayMs: 3000`; «Вернуть исходный» возвращает стандартные приветствия
без таймера. «Скачать JSON» экспортирует содержимое редактора в
`widget-integration.json`, не меняя подключение. Применённый код показан отдельно.
Не вставляйте сюда секреты: служебные параметры и токены редактор не принимает.

Готовые сценарии переключают рабочее время, нерабочее время и недоступность
сервиса без удаления переписки. В раскрываемой панели можно включить/выключить
автоматический ответ демо-оператора, отправить свой ответ или файл, показать
набор текста, отметить сообщения прочитанными и имитировать ошибку отправки.
Ответы предназначены для уже созданных диалогов. Сервис слушает только
localhost:4311; данные находятся в памяти и удаляются при его перезапуске.

Параметр страницы `?service=manager` подключает настоящий локальный сервис
на localhost:4314. При нём или любом другом адресе/идентификаторе вне локального
демо имитация отключена: редактор перезапускает только виджет и не меняет
настройки компании. Страница стенда и его служебный API не предназначены
для публикации вместе с производственным виджетом.

В демо: пн–пт 08:00–18:00 Europe/Moscow; обязательны имя, телефон и email;
до 5 файлов по 10 МБ; первое сообщение отправляется после формы. Это тестовая
конфигурация. Производственное расписание ещё нужно уточнить: в исходном
описании были варианты до 16:30 и до 18:00.

## Сборка и подключение

Для интегратора сайта: [Подключение готового виджета](docs/SITE_INTEGRATION.md).
Файлы виджета и сервис сообщений размещает команда PKSEP; интегратор вставляет
выданный готовый код.

Для нашей команды: [Сборка, размещение и настройки сервера](docs/WIDGET_HOSTING.md).

```powershell
bun run build
```

В `dist` находятся `manager.js` (обычный скрипт), `manager.mjs` (ES-модуль),
`widget.html` и `assets`. Разместить нужно весь каталог, сохранив структуру.

```html
<script type="module">
  import { mount } from 'https://manager.pksep.ru/manager.mjs'
  const widget = mount({
    siteId: 'amotiv',
    serviceUrl: 'https://manager.pksep.ru',
    widgetUrl: 'https://manager.pksep.ru/widget.html',
    offset: 24,
  })
  // При удалении интеграции: widget.destroy()
</script>
```

Названия, приветствия, расписание, лимиты и социальные ссылки приходят из
сервиса. Файлы виджета и сервис сообщений размещены на `https://manager.pksep.ru`.
`siteId: 'amotiv'` приведён как пример: наша команда заменяет его идентификатором
подключаемого сайта перед выдачей кода интегратору.
В iframe не передаются ключи чата/ЕРП. Загрузчик передаёт источник страницы
без query/hash, заголовок и origin перехода. Сервис обязан проверять эти данные.

## Проверки

```powershell
bun test tests/unit
bun run typecheck
bun x playwright install chromium
bun run test:e2e
bun run build
bun x playwright test --config playwright.production.config.ts
```

Если используется установленный Chrome, перед браузерными командами в
PowerShell: `$env:PLAYWRIGHT_CHANNEL = 'chrome'`.

Проверки включают 9 модульных тестов, 20 браузерных сценариев и отдельный сценарий
собранного загрузчика/iframe на разных origin. Визуально проверены приветствия,
форма, сообщения, меню и экран 375 px; касания проверены эмуляцией экрана 320 px.

Оформление обновлено по четырём SVG владельца задачи от 11.09.2026.
Размеры сохранены из описания: 418×640, шапка 76, редактор 120, кнопка 60×60.
Используются компоненты и семантические цвета sep-yui; локальные стили
виджета не меняют оформление остальных потребителей библиотеки.
Вектор `src/assets/company-mark.svg` извлечён из аватара начального экрана.
Фото `demo/assets/operator-avatar.png` экспортировано из офлайн-макета в
70×70 для демонстрационного автора и не входит в производственную сборку.

Время и статусы текста/контактов отображает общий ChatMessageMeta из sep-yui.
Одна галочка означает принятие сервисом, две появляются по readAt от сервиса.
В демо автоматический ответ имитирует прочтение; в панели также есть действие
«Отметить сообщения прочитанными». При недоступной отправке формы Tooltip
объясняет причину, используя те же правила, что проверяют контакты.

Открытый виджет можно перемещать за шапку; положение сохраняется до перезагрузки.
История и форма используют ScrollWrapper из sep-yui. Нижний отступ инструментов
редактора составляет 15 px при прежней высоте 120 px; его полоса прокрутки скрыта.
Плашки с переносами сжимаются по тексту и времени. Эмодзи подготавливаются
заранее, а редактор сохраняется после отправки.

Выбор файлов в виджете отправляет их без окна предпросмотра. При первом
обращении они ожидают контакты; в текущей переписке отправляются сразу
вместе с набранным текстом. Обычный СЭП Чат сохраняет предпросмотр.
У меню над круглой кнопкой убрана обрезаемая тень; зазор остаётся прозрачным.

Ограничения первого этапа: демонстрационная доставка не создаёт топики и
контакты ЕРП; файлы показываются общими карточками, полноценная галерея медиа
остаётся будущим расширением. Реальные Safari/iOS и Android, отзыв ролей,
серверное хранение и защита публичного приёма проверяются перед выпуском.
Текущий iframe использует общий пакет yui: JS около 2.36 МБ и CSS 699 КБ
(в gzip около 673 и 404 КБ). Загрузчик занимает 3.5 КБ, около 1.7 КБ gzip.
До публикации нужен отдельный лёгкий entry библиотеки и проверка загрузки
на мобильной сети; перенос всего chat-core не используется.
